# Integration Guide — Mini App API v0.6

How to build a client (Telegram Mini App, another frontend, a script or a
service-to-service integration test) against the Svoi Pravila Mini App API.
For a 5-minute local setup see [QUICKSTART.md](QUICKSTART.md).

## 1. Sources of truth

| Artifact | Path | Produced by |
| --- | --- | --- |
| OpenAPI 3.1 contract (JSON) | `docs/openapi.json` | `python scripts/export_openapi.py` |
| OpenAPI 3.1 contract (YAML) | `docs/openapi.yaml` | same script |
| Sample payloads | `docs/fixtures/*.json` | hand-curated, validated by `tests/test_contract_samples.py` |
| TypeScript DTOs | `clients/typescript/src/generated/openapi.ts` (generated by [openapi-typescript](https://openapi-ts.dev), aliased in `src/types.ts`) | `npm run generate` in `clients/typescript` |
| TypeScript client | `clients/typescript/src/` | `@svoi-pravila/miniapp-client` (local package) |

FastAPI/Pydantic models in `app/` are the real source of truth. The committed
files are exports of them, and drift is caught by tests:

```bash
python scripts/export_openapi.py --check                  # docs/openapi.* == fresh export
pytest tests/test_openapi_contract.py tests/test_contract_samples.py
cd clients/typescript && npm run check:generated           # openapi-typescript --check: src/generated/openapi.ts == docs/openapi.json
```

After changing a request/response model:

```bash
python scripts/export_openapi.py
cd clients/typescript && npm run generate && npm test
```

## 2. Authentication

Every `/v1/miniapp/*` request carries the **raw** Telegram `initData` string:

```http
X-Telegram-Init-Data: <Telegram.WebApp.initData, unchanged>
```

- The backend verifies the HMAC-SHA-256 signature with `TELEGRAM_BOT_TOKEN` and
  rejects `auth_date` older than `TELEGRAM_INIT_DATA_MAX_AGE_SECONDS` (default 3600).
- Identity is derived only from validated initData. Clients never send
  `user_id`, and `initDataUnsafe` is never trusted.
- There is no session token: send the header on every request.
- Local development: `examples/python/miniapp_client.py::sign_init_data(bot_token)`
  signs a valid initData with the same token the backend uses. Never ship this
  in a real client.

## 3. Endpoints

| Method | Path | Body | Success |
| --- | --- | --- | --- |
| POST | `/v1/miniapp/auth` | — | 200 `AuthResponse` |
| GET | `/v1/miniapp/bootstrap` | — | 200 `BootstrapResponse` |
| GET | `/v1/miniapp/relationships` | — | 200 `RelationshipView[]` |
| POST | `/v1/miniapp/relationships` | `RelationshipCreateBody` | 201 `RelationshipView` |
| PATCH | `/v1/miniapp/relationships/{relationship_id}` | `RelationshipUpdateBody` | 200 `RelationshipView` |
| DELETE | `/v1/miniapp/relationships/{relationship_id}` | — | 204 |
| PUT | `/v1/miniapp/me/default-relationship/{relationship_id}` | — | 200 `UserView` |
| POST | `/v1/miniapp/relationships/{relationship_id}/rules` | `RuleBody` | 201 `RelationshipRule` |
| PUT | `/v1/miniapp/relationships/{relationship_id}/rules/{rule_id}` | `RuleBody` | 200 `RelationshipRule` |
| DELETE | `/v1/miniapp/relationships/{relationship_id}/rules/{rule_id}` | — | 204 |
| POST | `/v1/miniapp/assist/{workflow}` | `MiniAppAssistBody` | 200 `DeliveryResponse` |

`workflow` is `soften`, `decode` or `help-say`. Request bodies reject unknown
fields (`additionalProperties: false`). Behavioral notes are in
[MINIAPP_API.md](MINIAPP_API.md).

### Assist responses

`DeliveryResponse.status` is `ok`, `blocked` or `error`; all three are HTTP 200.

- `ok`: `text` is the display text and `structured_result` holds the workflow
  artifact (`SoftenResult`, `DecodeResult` or `HelpSayResult`, see
  `docs/fixtures/delivery_*.json`).
- `blocked` / `error`: `structured_result` is `null` and `text` is a
  user-facing explanation.

`structured_result` is an open object in OpenAPI; the TypeScript client
provides typed guards (`getStructuredResult`, `isSoftenResult`, ...).

## 4. Errors

Non-2xx responses are JSON `{"detail": ...}`:

| Status | Meaning | `detail` |
| --- | --- | --- |
| 401 | initData missing, invalid signature or expired | string |
| 404 | relationship/rule does not exist **or is not owned** by the caller | string |
| 422 | request validation failed | list of `{loc, msg, type}` |
| 503 | Mini App auth not configured (`TELEGRAM_BOT_TOKEN` unset) | string |

Ownership failures are reported as 404 on purpose, so they don't reveal
whether another user's resources exist.

## 5. TypeScript client

`clients/typescript` is a local package with no runtime dependencies that ships TypeScript
sources (consumed by Vite/tsc via `moduleResolution: "bundler"`).

Pipeline: FastAPI/Pydantic → `docs/openapi.json` → `openapi-typescript`
(`--default-non-nullable false`, so request fields with backend defaults such as
`set_as_default` and `priority` stay optional) → `src/generated/openapi.ts` →
handwritten `createMiniAppClient`, errors and runtime guards. The generated file
is never edited by hand; `src/types.ts` only re-exports its schemas under short names.

```jsonc
// package.json
"dependencies": { "@svoi-pravila/miniapp-client": "file:../clients/typescript" }
```

```ts
import { createMiniAppClient, getStructuredResult, isMiniAppApiError } from "@svoi-pravila/miniapp-client";

const client = createMiniAppClient({
  baseUrl: "",                                            // "" = same origin; or "https://api.example.com" (string or getter)
  getInitData: () => window.Telegram?.WebApp?.initData,   // () => string | null | Promise<...>, called per request
  fetch: (input, init) => fetch(input, init),             // required; the client has no global fallback
});

const { user, relationships } = await client.bootstrap();
const delivery = await client.assist("soften", { text: "…", language: "ru" });
const result = getStructuredResult(delivery); // SoftenResult | null
```

- The client is runtime-independent: `baseUrl`, `getInitData` and `fetch` are
  all injected, and the package never reads `window`, `globalThis.fetch`, Node,
  Telegram or Vite globals. The same client works in browsers, Node 20+, workers and tests.
- Missing initData rejects with `MiniAppApiError(401)` **before** any network call.
- Non-2xx responses throw `MiniAppApiError` with `status`, `detail` (always a
  string), `validationErrors` (for 422) and the raw `body`.
- Network failures propagate as `TypeError`; `toErrorStatus(err)` maps
  errors to `status | 0 (network) | 500 (unknown)`.
- Path parameters are URL-encoded.

The Mini App frontend (`frontend/src/api/`) is a thin adapter over this package.

## 7. Compatibility policy

- `/v1/miniapp/*` is the public client surface. `/v1/assist/*` is also described
  in the full OpenAPI document, but it is an internal API and is not exposed by
  the public Mini App TypeScript client.
- Version metadata (`info.version` in OpenAPI, `/health`, `API_VERSION` in
  the TS client) is `0.6.0`.
- Additive response fields are non-breaking; clients must ignore unknown
  response fields. Removing or renaming fields, or tightening request
  validation, is breaking and requires regenerating the contract and client.
